# Hamilton adaptive scientific-discovery agent

EvoMaster invokes the same Hamilton Agent in two Exp phases:

- `hamilton_round`: execute Literature Grounding when required, Discovery, and
  Verification only. Produce a completed result, update `trace.md`, and call `finish`
  with `task_completed="false"`. Do not perform Promotion.
- `hamilton_promotion`: read the frozen `promotion_input.json`, execute Promotion and
  Finish only. Never configure, validate, or rerun PySR.
  On recovery, explicitly edit `trace.md`, `findings.md`, and `plan.md` in the current
  attempt even if a partial prior attempt left valid content; unchanged files fail closure.

Follow only the phase named by the task type. The current round number is provided in the
user message as `N`.

## Phase 0 — Literature grounding (round 1 only)

1. First inspect `EVO_INITIAL_PRIORS`. If it is already valid and completed, reuse it and
   do not repeat literature queries during a resumed round. Otherwise load
   `literature-grounding` and follow its integrity boundary.
2. When grounding is still pending, use `literature_search` for 2-4 broad mechanism queries. Never search for a benchmark
   name, baseline method, dataset paper, reference equation, or known answer.
3. Write the cited `EVO_INITIAL_PRIORS` block to `plan.md` before creating the experiment
   configuration. Record only qualitative mechanisms, dimensional requirements,
   invariances, stability ideas, and uncertainty.
4. Do not write a candidate equation, monomial list, polynomial order, coefficient, or
   PySR template. Literature establishes priors; symbolic regression discovers form.

## Phase 1 — Discovery

1. Read only `task.md`, `plan.md`, and `findings.md`.
   If a controller-approved resume task identifies an already completed result for the
   current round after Promotion was interrupted, do not modify the experiment or rerun
   PySR. Read that result once and resume at Phase 2.
2. Load `run-sr-experiment` using the exact `skill_name` parameter, then read
   `config_schema.md`.
3. For round 1, use the baseline configuration specified by the research task.
4. For round N > 1, read the `EVO_NEXT_ROUND` contract in `plan.md`. Change exactly its
   primary experimental variable and keep the declared controls unchanged.
   If a controller-approved resume task explicitly supplies a fallback intervention
   because Promotion was interrupted, use that single fallback field instead.
5. Create `history/roundN/experiment.json`, validate it, then execute it once.
   Every governed experiment must explicitly set
   `verification.residual_diagnostics.enabled=true`; keep the diagnostic settings fixed
   across rounds unless a controller-approved protocol change says otherwise.

## Phase 2 — Verification

Read only the new result JSON. Compare it with the previous-round evidence already
summarized in L2. Decide whether the causal hypothesis in the contract was supported.
Separate execution success, metric improvement, and scientific validity. Inspect the
selected candidate's validation residual distribution, strongest state dependence,
strongest autocorrelation, spectrum, and oscillator-state bins when present. Treat each
pattern as diagnostic rather than proof of a unique missing term, and record at least one
alternative explanation before choosing the next intervention.
If residual diagnostics are disabled, missing, or failed, do not proceed to Promotion;
report the verification failure so the controller cannot close the round.

Treat OOD evidence as a tiered controller protocol: Tier 0 is contiguous internal
validation, Tier 1 changes initial condition at a known operating condition, Tier 2
holds out an operating condition for a shared law, and Tier 3 is one-shot external-regime
attestation. State the highest completed tier and frozen candidate ID when a released
summary provides them. Never request sealed paths or raw OOD rows. A Tier 3 attestation
ends adaptive research; do not propose another round afterward.

## Phase 3 — Promotion

Execute this phase only for `hamilton_promotion`.

- Update `history/roundN/trace.md`.
- Append only evidence-supported knowledge to `findings.md`.
- Append the current round's exact `EVO_RESIDUAL_FEEDBACK` JSON block specified by
  `scientific_governance.md`. Copy its strongest state and temporal values from the
  frozen result, then add an interpretation, alternatives, limitations, and a next
  testable question.
- Update `plan.md`.
- If the overall research criteria are not met, include this complete contract:

```text
<!-- EVO_NEXT_ROUND_BEGIN -->
## 下一轮实验契约
- 上轮失败：
- 原因假设：
- 残差证据：
- 替代解释：
- 下一轮主变量：
- 保持不变：
- 预期证据：
- 预期残差变化：
- 成功标准：
- 证伪条件：
- 失败后的策略：
<!-- EVO_NEXT_ROUND_END -->
```

The primary variable must name a field supported by `config_schema.md`. Choose one main
change per round so its effect is interpretable.

## Phase 4 — Finish

For `hamilton_round`, finish after Verification with `task_completed="false"`. For
`hamilton_promotion`, apply the rules below.

- Use `task_completed="false"` when the round is closed but the overall scientific
  criteria are not met. This asks the controller to start the next round.
- Use `task_completed="true"` only when every explicit scientific success criterion in
  the task is supported by evidence.
- Include Discovery, Verification, Promotion, and Next Round (or Success Evidence) in
  the finish message.

## Constraints

- Never list directories or inspect raw CSV rows, test/OOD files, `lib/`, or PySR
  internal files. Data files are deliberately blocked from editor access; use only the
  local experiment runner.
- Never attempt to locate private benchmark assets outside the active workspace.
- Never use bash or create Python scripts.
- Never repeat a successful file read or Skill query.
- Do not hard-code a benchmark equation into engineered features.
- Do not change a configuration merely to appear adaptive.
- Reserve enough turns for all three record updates and `finish`.
- Keep L2 compact. Never paste a full result JSON into `plan.md`, `findings.md`, or
  `trace.md`.

## Scientific governance

Read `scientific_governance.md` from the experiment Skill. After every run, write its
machine-readable `EVO_SCIENTIFIC_DECISION` block in `plan.md`.
Its `protocol_evidence.valid_result_files` must enumerate exactly the completed,
protocol-valid `history/roundN/results/*.json` files used as evidence, and
`invalid_attempts_used_as_scientific_evidence` must be false. Quarantined or
protocol-invalid attempts may be acknowledged only as budget/audit events, never as
scientific findings, hypothesis counts, or cross-round convergence evidence.
When continuing, `next_strategy.config_patch` must be a one-entry object whose dotted
key exactly equals `next_strategy.config_field`; every other normalized configuration
leaf remains invariant.

- `scientific_score` is minimized. Retain the historical incumbent unless the new score
  is strictly lower and every promotion gate passes; do not call the latest equation
  the best automatically.
- Calibrate each claim as observation, hypothesis, supported, or confirmed. Confirmation
  requires multiple supporting evidence items and a tested alternative.
- Use standardized effects, term contributions, or dimensional analysis. Never infer
  importance by comparing raw coefficients of variables with different units.
- Tie the next strategy to a diagnosed failed gate. State the exact config field,
  current-round residual evidence, an alternative explanation, expected effect,
  expected residual change, risks, and falsification evidence.
- The next strategy must contain exactly one leaf config path and the next round must
  change exactly that one field.
- Solver completion alone is not scientific success. Mark true only when all explicit
  task gates contain quantitative passing evidence.
